# Cali MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Cali Go CLI (`init add list show find status update remove sync import`; `import` removed 2026-10-17, issue #13) as specified, in three milestones (walking skeleton, daily commands, safe update).

**Architecture:** Small `internal/` packages with one responsibility each, wired by a thin `internal/cli`. All git work goes through the system `git` binary; all state is plain files (`cali.yaml`, `cali.lock`, pristine store). Update is a plan phase (pure, testable) followed by a staged apply phase.

**Tech Stack:** Go (module `github.com/rojcarranza/cali`), system `git`, one YAML library, one CLI framework, one terminal styling library (the last three chosen in Task 1 ADRs). Tests: `go test -v ./...`; lint: `golangci-lint run`; format: `gopls`.

**Spec:** `docs/superpowers/specs/2026-10-16-cali-design.md` (brief: `docs/brief.md`). Section numbers below (§) refer to the spec.

## Global Constraints

- One phase/task at a time; tests first; a task is done only when its verify command passes (`CLAUDE.md`).
- No new dependency, datastore or service without an ADR in `docs/adr/` (`CLAUDE.md`).
- Never touch `.env*` files. Never edit `.gitignore`. Ask before deleting, overwriting or renaming existing files.
- Single static binary per OS; macOS, Windows (Git Bash, no admin) and WSL Ubuntu. Do not assume GNU coreutils or `/` separators; use `filepath` for disk paths and `/` inside lock and manifest.
- Budget EUR 0, open-source tools only. Cali never calls an LLM.
- Files are copied, never symlinked. Bytes installed = bytes in the git commit (§4).
- Lock bytes: sorted keys, 2-space indent, `\n`, trailing newline, no timestamps, no absolute paths (§4).
- Tokens only from `GITHUB_TOKEN`/`GH_TOKEN` or `gh auth token`, passed to git via `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n`, only for `github.com`; never in argv, files or logs (§10).
- Commits: Conventional Commits with scope, imperative subject, no trailing period. Author and committer are Roj only; no Claude co-author, trailer or footer.
- Target dirs: `claude` = `.claude/skills` / `~/.claude/skills`; `copilot` = `.github/skills` / `~/.copilot/skills` (§6).
- Update never writes `<<<<<<<` markers into installed files; every `theirs` choice first writes a backup and `local.patch` (§5).

## Review Focus

1. A text file with CRLF on disk (Windows editor) must not show as `modified` (Task 6).
2. Skill folder containing a symlink, `..` path or `NUL.md` must fail `add`/`sync` naming the path and write nothing (Task 6).
3. `SKILL.md` frontmatter `name` differing from the folder name must be rejected at `add` with both names in the message (Task 7).
4. Update interrupted or failing midway (rename error) must leave the original folder and lock intact (Task 16).
5. Upstream force-push removing the locked commit, or a missing pristine dir, must give `base-lost` and no crash; `status` with no network must warn, not fail (Tasks 10, 14).
